CHECK 8 — OG + TWITTER TAGS vs META TAGS
Result: ❌ FAIL — Twitter tags wrong on ALL 29 pages
================================================================================

OG TAGS: ✅ PASS
  og:title matches meta title on all 29 pages — correct.
  og:description matches meta description on all 29 pages — correct.
  og:image present on all 29 pages (same brand image across all pages).

TWITTER TAGS: ❌ FAIL — SAME TWO BUGS on all 29 pages

BUG A — twitter:description is hardcoded to the philosophy page text on ALL pages:
  Wrong value on every location page:
    "At Flourish Early Learning Centre, we believe every child is a capable,
     curious, and confident learner with the right to feel safe, valued and
     empowered."
  This is the philosophy page's description — it is appearing on every location
  page instead of the page's own meta description.

BUG B — twitter:title does NOT match the SEO meta title:
  The twitter:title is pulling from the WordPress page title (e.g., the old
  slug-style title), not from the SEO plugin-set title.

  Examples of the mismatch:
  Page                              Meta Title (correct)                 Twitter Title (wrong)
  /daycare-childcare-oakville-nsw/  Childcare Oakville | Flourish ELC    Daycare Childcare Oakville NSW | Flourish Early Learning Centre
  /preschool-oakville-nsw/          Preschool Oakville NSW | Flourish ELC  Preschool Oakville NSW | Flourish Early Learning Centre
  /kindergarten-bull-creek-wa/      Kindergarten Bull Creek | Flourish ELC  Kindergarten Bull Creek WA | Flourish Early Learning Centre
  /areas-we-serve/                  Childcare Near Me | Flourish ELC     Areas We Serve | Flourish Early Learning Centre

ROOT CAUSE:
  The WordPress SEO plugin (Yoast/RankMath) correctly sets the meta description
  and og:title/og:description per page. However, the twitter:title and
  twitter:description are not inheriting these — they're falling back to the
  WordPress default page title and a global site description.

  This is most likely because when the location pages were built, the "Social"
  tab in the SEO plugin was not filled in for each page. The plugin is using a
  global/fallback value instead of the page-specific SEO values.

FIX REQUIRED (developer action):
  In WordPress, for each location page:
  Option A (Recommended): In Yoast SEO → go to the "Social" tab → enable
  "Use meta title/description for Twitter" (or equivalent toggle in RankMath).
  This makes Twitter tags automatically mirror the SEO title/description.

  Option B: Manually enter the Twitter title and description for each of the
  29 pages in the Social tab of the SEO plugin.

  The root cause (philosophy page description appearing everywhere) suggests
  there may also be a global fallback set — check Yoast/RankMath global
  settings → Social → default/fallback description and clear it.

OG IMAGE NOTE (not a failure, just an observation):
  All 29 pages use the same og:image (Flourish-ELC-8-800x534.jpg).
  When links are shared on Facebook/LinkedIn, they all show the same image.
  Consider setting page-specific images for location pages to improve social
  click-through rates.

CHECK 9 — CLICK-TO-CALL (mobile phone number tapping)
Result: ⚠️  FUNCTIONAL but with encoding bug on Bull Creek number
================================================================================
Phone numbers are wrapped in tel: links on all 29 pages — click-to-call works.
However, the Bull Creek WA number has a URL encoding issue in 2 of its 3
appearances on every page:

  WRONG:   href="tel:08%206234%208570"  (spaces URL-encoded — may fail on some devices)
  CORRECT: href="tel:0862348570"        (no spaces — universally compatible)

Impact: This affects all 29 pages (the encoded version is in the global site
header or footer). On most modern smartphones, both formats work, but the
encoded version with %20 is technically invalid for tel: URIs and can fail
on older Android/iOS browsers or certain CRM integrations.

FIX REQUIRED (developer action):
  In the WordPress template (header/footer or Beaver Builder global row),
  find the Bull Creek phone anchor and change:
    href="tel:08%206234%208570"   → href="tel:0862348570"
  This appears in 2 out of 3 link occurrences per page. The third is already
  correct. Fix whichever template element generates the two broken instances.
